ani-scrapy

Python scraping library published on PyPI

ani-scrapy

The Problem

Building Anime Scraper required pulling data from multiple sources with completely different HTML structures. The naive approach — writing a separate scraper for each site inline — would have made the codebase a maintenance nightmare. Adding a new source would mean digging into application logic every time.

The Approach

I extracted all scraping logic into a standalone Python library with a unified abstract interface. Each source implements a common contract: search, get episode list, get download links. The consuming application never talks to a source directly — it talks to the interface. Publishing on PyPI was a forcing function for doing it right: proper packaging, versioning, and documentation.

What I Learned

Designing a good abstract interface is harder than it looks. My first version was too tightly coupled to the first source I scraped — I had to refactor significantly when I added the second. The lesson: design the interface from the consumer's perspective, not the implementation's. I'd also add automated tests for each source from the start — scraping breaks silently when a site changes its HTML.
